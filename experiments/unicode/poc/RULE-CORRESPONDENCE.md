# ICU `gennorm2` To re2c Correspondence Ledger

Reference notation: ICU 78.3 `nfc.txt`, documented under the ICU Normalizer2
`gennorm2` data-file syntax. Normative behavior: Unicode 17.0.0 UAX #15 and
`NormalizationTest.txt`.

| ICU/manual surface | Meaning used by NFD | re2c transcription | Semantic adjustment |
| --- | --- | --- | --- |
| `* Unicode 17.0.0` | declares the data version | version-token rule with captured dotted number | exact version is required; any other value fails |
| `0300..0314:230` | inclusive range has non-zero ccc 230 | tagged hex range, colon, tagged decimal value | expanded into the PoC's lookup vector; overlaps and zero values fail |
| `0315:232` | one code point has non-zero ccc 232 | tagged single hex value, colon, tagged decimal value | stored through the same validated range path |
| `00E1=0061 0301` | two-way canonical mapping | tagged source, `=`, tagged code-point sequence | NFD uses the decomposition direction only; exactly two targets are required as `gennorm2` specifies |
| `0340>0300` | one-way canonical mapping | tagged source, `>`, tagged code-point sequence | NFD uses the mapping exactly as written; one or more targets are accepted |
| comments/blank lines | non-semantic layout | explicit whole-line rules | malformed or partially recognized lines fail with file and line |
| implicit ccc 0 | starter/default class | zero-filled lookup for all scalar values | only explicit non-zero rules may overwrite defaults |
| recursive mappings | full canonical decomposition | recursive action over captured mappings | cycles and excessive depth fail rather than loop |
| predefined Hangul/Jamo | algorithmic decomposition outside `nfc.txt` | UAX #15/Core algorithm in the reference action | syllables expand to L/V[/T]; no generated table is invented |
| canonical ordering | stable ascending non-zero ccc within each starter segment | stable insertion step after full decomposition | equal ccc values retain input order; ccc 0 blocks movement |
| end of file | complete rule set | explicit NUL sentinel rule | embedded NUL and unmatched input are errors |

## Minor Translation Differences

1. re2c recognizes the notation; ordinary C++ actions hold the temporary
   logical rule model and execute normalization. The PoC does not claim that
   re2c itself supplies Unicode normalization semantics.
2. ICU's generator builds a compact `.nrm` implementation supporting
   composition as well as decomposition. This proof consumes the same rule
   meaning but intentionally stops at NFD, the previously achieved boundary.
3. The PoC retains a direct code-point lookup vector for ccc and a map of
   variable-length decompositions. Those are clear oracle structures, not a
   proposed CREXX packed-binary layout.
4. The conformance scanner is also generated by re2c. This exercises named
   lexical definitions, sequence fields, rule priority, EOF, and diagnostics
   without importing ICU parser code.

## Capabilities Demonstrated For Later Level L Work

- named lexical definitions and composition;
- literals, ranges, concatenation, alternation, optionality, and repetition;
- deterministic priority for overlapping line forms;
- captured source spans without copying the whole fixture;
- typed actions that emit version, range, mapping, section, and test records;
- one-to-many mapping expansion and recursive actions;
- explicit EOF and fail-closed malformed-input diagnostics;
- state held outside the generated scanner (rule tables and current test part);
- deterministic regeneration of readable reference source; and
- separation of lexical recognition from normalization semantics.

The proof does not demonstrate a need for start conditions, trailing context,
captures beyond field spans, a streaming refill protocol, or arbitrary
embedded host-language actions in the eventual CREXX-native specification.
