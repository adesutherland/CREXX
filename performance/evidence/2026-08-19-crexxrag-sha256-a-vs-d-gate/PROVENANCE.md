## Sampling contract

All cells ran serially with one warmup and three recorded observations through
`performance/tools/run_cross_runtime.crexx`. Five short process/native series
crossed the governance 10% min/max-span trigger, so ten unchanged serial
observations were appended in separate `*-append` cells with the original
samples retained. Reported medians combine all 13 observations for those
series. Some millisecond-scale process cells remain noisy after the required
append and are interpreted only as startup-inclusive diagnostics; the stable
hash-kernel medians own the A/D decision.

Each cell manifest contains the exact argv. `elapsed_ns` is process-inclusive.
`benchmark_metric` is the program-reported steady-state `elapsed_us`;
deterministic input construction and final correctness comparison are outside
that timed kernel.

Equal work within every A/D lane:

- 64 bytes x 20,000 hashes;
- 4,096 bytes x 500 hashes; and
- 1,048,576 bytes x 2 hashes.

The same generated byte at offset `i` is `(i * 31 + 7) mod 256`. Every sample
observed the expected digest. The direct-C control uses the same bundled
`rx_sha256()` implementation as the native RXPA test plugin.

## Qualification commands

```text
cmake --build cmake-build-release --target performance_crexxrag_sha256 --parallel 10
ctest --test-dir cmake-build-release -R '^crexxrag_sha256_a_vs_d_(noopt|opt)$' --output-on-failure --parallel 2
cmake-build-release/bin/rxtvm <linked-image> <test-plugin> -a selftest
cmake-build-release/bin/rxbvm <linked-image> <test-plugin> -a selftest
```

Each timing cell was then run through the Level B
`performance/tools/run_cross_runtime.crexx` tool. The full absolute command,
workload, runtime, variant, warmup/run counts, timestamps, host description and
result are retained in that cell's `manifest.json`.
