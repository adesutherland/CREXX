The Quick_Check table is unused by normalize(). Fifteen of the sixteen CREXX
normalization cells moved by no more than 9.34% against the immediately prior
directional run; the outlying rxtvm shared NFC row cell was 13.25% slower while
its rxbvm peer was 0.26% faster. With one warmup and three samples on a
non-dedicated host this is neutral/noisy evidence, not an algorithm regression
or improvement claim.

In the final rerun, shared/canonical normalization ratios range from 0.940x to
1.103x. The 1.103x outlier is the noisy rxtvm NFC row cell; its rxbvm peer is
0.996x and all other ratios are 0.940x to 1.024x. Together with the RXAS shape,
this confirms that the constant pool is not copied per normalizer and is no
longer carrying the old shared-path penalty.

For the mixed true/false rows, the shared NFC predicate improves 3.893x on
rxtvm and 3.990x on rxbvm; shared NFKC improves 4.245x and 3.870x. Canonical
NFC improves 4.057x/3.976x and canonical NFKC 4.213x/4.224x. The Apple row
controls remain in the same band.

The known-normalized joined NFC/NFKC buffers contain at least one official
Maybe value. The canonical algorithm therefore completes its preliminary
Quick_Check scan and then invokes the whole-input exact fallback. Against the
old exact-stream-only path, shared NFC is 9.99%/9.92% slower and shared NFKC
is 10.97%/11.17% slower on rxtvm/rxbvm. Canonical NFC is 10.55%/11.83% slower
and canonical NFKC is 8.15%/13.38% slower. This is the expected cost shape of the
selected canonical No/Maybe/Yes front end; it is not an across-the-board
predicate improvement.

The rows cover true and false outcomes. The corrected large-buffer cells use
the known-normalized expected buffer, so they force a complete true-path scan.
The first run's source-buffer predicate cells in run.wlMGUE short-circuited on
an early false result and must not be reported as full-buffer throughput; the
corrected predicate authority is run.xfj3sN.

Apple conformance boundary
  Apple transform row mismatches: NFD 2, NFKD 2, NFC 46, NFKC 53.
  Apple predicate row mismatches: is-NFD 2, is-NFKD 2, is-NFC 43, is-NFKC 38.
  The Apple numbers are therefore native platform magnitude controls, not
  Unicode 17 semantic peers.

Review conclusion
  The four normalize(.string) forms now share the intended RXVM codepoint
  architecture and one immutable table constant. The previous compatibility
  and composition slowdown was an algorithm/routing problem, not re2c or RXVM
  UTF-8 decoding in the current path.

  D-form is_normalized() remains a direct codepoint/table quick rejection and
  CCC-ordering pass. C-form is_normalized() now implements the official Unicode
  17 Quick_Check No/Maybe/Yes front end from the same single sealed constant:
  No rejects, an all-Yes ordered scan accepts, and Maybe selects the existing
  exact allocation-free streamer. The codepoint scan lets RXVM perform UTF-8
  decoding and never copies the prepared table into a normalizer instance.

  The row result validates the common fast path. The normalized-buffer result
  also exposes the canonical algorithm's deliberate limit: any Maybe selects
  a whole-input fallback. A stable-region/local-Maybe implementation could
  avoid that repeated prefix work, but that would be a distinct follow-on
  algorithm and is not justified by this correction alone.
