# NR-06 first Release verdict

Status: **no demonstrated win; provisional production candidate awaits Adrian's direction**.

## Scope and provenance

- Source branch/HEAD: `develop` at `5e5e3b397`, with the NR-06 typed scalar
  call-window candidate and its focused tests uncommitted. The validated NR-07
  lowering PoC was removed from production code before this measurement.
- Host: Darwin 25.5.0 arm64, Apple M5, 10 logical CPUs.
- Toolchain: Apple clang 21.0.0, Ninja, `CMAKE_BUILD_TYPE=Release`,
  `CREXX_VM_PROFILING=OFF`.
- Product build: ordinary full profiling-off Release build, `cmake --build
  cmake-build-release -j 32`, completed successfully.
- Workload: canonical `tests/benchmarks/awfy_permute.crexx`, optimized,
  repetitions `50`, linked and stripped with the same current Release `rxas`,
  `rxlink`, and `library.rxbin` for baseline and candidate.
- Lifecycle: serial process runs; two warmups and nine recorded samples per
  image/VM cell. `rxvm` ran baseline then candidate; `rxbvm` ran candidate then
  baseline as an order control.
- Correctness: all 44 warmup/recorded executions exited zero and contained
  `PASS: AWFY Permute` with result `8660`.

The retained older timing bundles do not use the exact final Release VM binary,
so this gate used a bounded same-product drift control. The baseline RXAS was
generated before the Release rebuild by the pre-batch Release compiler
(`db94bc9ca`, binary SHA-256
`013fee4e4d6ac869d1d873e7d7a59bdc1ebb4d294e1cdb3f9c0a15a28f1da827`).
There are no compiler or benchmark-source commits between that compiler and
the current clean HEAD. The candidate RXAS was generated by the frozen NR-06
Release compiler. Both were then assembled and linked by the same newly built
product.

## Release timing result

Lower process elapsed time is better.

| VM | Baseline median | Candidate median | Change | Baseline range | Candidate range |
|---|---:|---:|---:|---:|---:|
| `rxvm` | 82.497 ms | 85.276 ms | +3.369% | 80.555–87.453 ms | 82.741–126.484 ms |
| `rxbvm` | 83.690 ms | 83.479 ms | -0.252% | 83.445–84.169 ms | 83.159–84.846 ms |

`rxbvm` is neutral. The `rxvm` candidate median is adverse and its sample set
contains several large high-side outliers, so it is materially noisy rather
than evidence of a reliable improvement. The first Release gate therefore does
not accept NR-06 as a performance win. Rework and revert remain live outcomes;
no wider portfolio, rerun, NR-07 production work, or closeout validation was
performed after this verdict.

Raw stdout/stderr, exact argv, timestamps, versions and per-sample elapsed
times are retained under `cells/`. These values are process-lifecycle
observations for the exact image and host above, not a general steady-state
kernel claim.
