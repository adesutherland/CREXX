MAIN EXAMPLES

Both models: passed 3825 generated tips each (all three games, every count
1-50), checking number counts, ranges, sorting, uniqueness within each pool
and formatting. Counts were validated before conversion; empty, 0, 51,
negative, decimal, overlong, alphabetic and expression-like input were rejected.
Save, replacement/truncation, saved result identity and save failure passed.
cREXX model checks passed with both ordinary optimization and -n builds.

ANSI: tested in real foreground pseudo-terminals. Keyboard entry, 50-tip
paging, independent inspection of saved Euro/German number pools, two-step Save,
invalid entry, mouse press/release matching, numeric paste, command-looking paste
isolation, resize, save failure/recovery and Quit/Ctrl-C passed. Saved termios,
alternate-screen exit and cursor restoration were checked. Startup/Generate did
not write the tips file.

Swing: actual radio buttons, text field, Generate/Enter, results area, Save logic
and Quit were exercised on the event-dispatch thread. Tests covered exclusive
choice, 50 Euro tips, invalid entry keeping results, changing selection without
relabelling saved results, file write failure and subsequent recovery. Both
checks and the application run with classpath '.' only, without a NetRexx JAR.
The file chooser and physical Windows mouse interaction still need manual checks.
