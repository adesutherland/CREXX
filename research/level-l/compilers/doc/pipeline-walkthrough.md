# One program through both frontends

The source trees and IR below are generated by the implemented Level B C/G
frontends using Level L. The [STEP04 outputs](../examples/step04/README.md)
complete the path through actual RXAS, assembly, linking and execution.
The Classic views use the current context/entry ABI and one source-unit body;
G retains its own typed construction. The [STEP06 walkthrough](../examples/step06/README.md)
shows source trees, original/optimised IR, RXAS and error variants. Shared IR
optimisation is covered by the [profile matrix](poc-coverage.md).

## Source and intended result

The [C program](../examples/step01/pipeline-c.crexx) begins:

```rexx
options levelc
total = 2 + 3
if total > 4 then say twice(total)
else say 0
```

The [G program](../examples/step01/pipeline-g.crexx) selects `options levelg`,
imports `rxfnsb` and declares `total = .int` before assigning it. Each complete
program counts total down to zero, prints it, calls LENGTH, and exits. C uses
`'α漢🙂'`; G retains `'cat'`. Both contain three codepoints, while the C literal's
UTF-8 payload occupies nine bytes. The local routine `twice` has ARG and RETURN.
Both programs are expected to print `10`, `0`, `3`, on separate lines. Their variable and numeric meanings differ.

An independent native C comparison must configure UTF8, use the existing LENGTH
BIF, state compiler and assembler optimisation separately and link the same
runtime owners explicitly. Native output is a control, not the language oracle.

## Tokens and source trees

For `total = 2 + 3`, the generated lexer identifies a name, equals sign,
numeric spelling, plus sign and numeric spelling, preserving byte ranges.
The context stage identifies the clause and any implicit concatenation; the
LR parser and `then tree` mappings construct an `Assignment` with text field
`name` and child field `value`.

The value has a Chain at each precedence level. Most contain one operand and
are transparent during lowering. The additive Chain has two Number operands
(with transparent wrappers) and one `plus` operator. G additionally retains
Cast wrappers, even when their target lists are empty. These actual schema
shapes replace the earlier illustrative Add/Literal notation; see the
[tree reference](trees-and-ir.md) and [complete generated trees](../examples/step03/README.md).

G's table resolves TOTAL to an int64 binding, with an entry default. Classic
keeps the uppercase dynamic pool name TOTAL and exact numeric spelling.
Classic labels and PROCEDURE remain separate source constructs; G procedures
own their body and typed parameter/result declarations.

The actual C tree reports `String|139:150|'α漢🙂'`: the half-open byte range
includes both quotes. In RXAS the same authored literal has line 9, Unicode
columns 12–17, end-exclusive. Byte ranges, Unicode columns and LENGTH's
codepoint result describe different coordinates and are preserved separately.

## Actual G entry IR

```text
function $MAIN -> crexx.g.int64
  entry.1:
    %1 = core.constant 0 : crexx.g.int64 @origin:2
    core.store %1 slot:TOTAL @origin:2
    %2 = core.constant 2 : crexx.g.int64 @origin:14
    core.store %2 slot:$tmp.1 @origin:11
    %3 = core.constant 3 : crexx.g.int64 @origin:17
    %4 = core.load slot:$tmp.1 @origin:11
    %5 = crexx.g.int64.add %4 %3 @origin:11
    core.store %5 slot:TOTAL @origin:6
    %6 = core.load slot:TOTAL @origin:26
    core.store %6 slot:$tmp.2 @origin:21
    %7 = core.constant 4 : crexx.g.int64 @origin:31
    %8 = core.load slot:$tmp.2 @origin:21
    %9 = crexx.g.int64.gt %8 %7 @origin:21
    %10 = crexx.g.truth %9 @origin:18
    core.branch %10 -> if.yes.2 -> if.no.3 @origin:18
```

The saved `$tmp.1` retains the evaluated left operand before lowering the right
operand. This initially conservative scheme works even when that operand
creates a short-circuit subgraph or calls a routine. The shared
optimiser now substitutes proved same-block temporaries; it keeps state and
cross-block obligations. `%9` is G's Boolean carrier;
`crexx.g.truth` converts it to the canonical Boolean required by the core branch.
SAY in each successor converts its selected value to text and remains an
observable output operation.

## Actual Classic entry IR

```text
function $MAIN -> crexx.c.result
  argument 1 crexx.c.context required
  argument 2 crexx.g.int64 required
  entry.1:
    %1 = core.argument argument:1 @origin:2
    core.store %1 slot:$context @origin:2
    %2 = core.argument argument:2 @origin:2
    core.store %2 slot:$entry @origin:2
    core.jump -> entry.dispatch.2 @origin:2
  entry.dispatch.2:
    %3 = core.load slot:$context @origin:2
    %4 = core.load slot:$entry @origin:2
    %5 = crexx.c.entry.test %3 %4 id="0" name="" @origin:2
    core.branch %5 -> source.main.3 -> entry.next.5 @origin:2
  source.main.3:
    %10 = core.load slot:$context @origin:10
    %11 = crexx.c.load %10 name="levelc" @origin:10
    %12 = core.constant 32 : crexx.c.value @origin:18
    core.store %12 slot:$tmp.1 @origin:16
    %13 = core.constant 33 : crexx.c.value @origin:20
    %14 = core.load slot:$tmp.1 @origin:16
    %15 = core.load slot:$context @origin:16
    %16 = crexx.c.add %14 %13 %15 @origin:16
    %17 = core.load slot:$context @origin:11
    crexx.c.store %17 %16 name="total" @origin:11
    %18 = core.load slot:$context @origin:28
    %19 = crexx.c.load %18 name="total" @origin:28
    core.store %19 slot:$tmp.2 @origin:24
    %20 = core.constant 34 : crexx.c.value @origin:32
    %21 = core.load slot:$tmp.2 @origin:24
    %22 = core.load slot:$context @origin:24
    %23 = crexx.c.gt %21 %20 %22 @origin:24
    %24 = core.load slot:$context @origin:21
    %25 = crexx.c.truth %23 %24 @origin:21
    core.branch %25 -> if.yes.7 -> if.no.8 @origin:21
```

The header remains `COptions` in the source tree and performs the ordinary
`levelc` Name read before the assignment. Its current empty processor emits no
call. The source AST and executable dispatch remain separate contracts.

`32`, `33` and `34` are hex byte spellings for `2`, `3` and `4`; Classic values
are not silently canonicalised to G integers. Pool operations retain raw source
spelling in their `name` attribute; the shared pool owns normalization. The
required context argument is stored as a reference-valued local alias and read
for each contextual operation. A second required integer argument selects the
checked main/label entry in one source-unit body; the
[current C ABI](levelc-architecture.md#proposed-procedure-contract) owns that protocol. The bundle borrows live
activation, pool and configuration owners; pool reads observe its current binding.
The caller constructs stable child owners after completing the argument packet,
inherits numeric state and passes its bundle reference plus the declared entry ID. Child updates leave the
parent activation and restored VM frame unchanged. Argument/result packets
separately retain omission and returned-value presence. The entry wrapper owns
main's initial state and the shared UTF8 configuration.

## Loops, calls and short-circuiting

The G pipeline contains `while.test`, `while.body` and `while.after` blocks;
Classic's normalized CDo uses `do.while`, `do.body` and `do.after`.
LEAVE targets the after block; WHILE's ITERATE targets its test. Block edges,
rather than printed layout, define execution order. G's source variable is a
typed local slot; Classic reads and writes its pool, including the defined
unset-name behaviour, and uses contextual `crexx.c.while.truth`.

A G call has a registered typed signature and `target="TWICE"` attribute. A
Classic call carries its original argument packet, the borrowed context and a
function/subroutine attribute, and yields a result-presence packet. CALL updates
RESULT/.RESULT; expression use requires a value. Static quoted targets bypass
local labels, and direct BIF bindings preserve the original presence vectors.
Authored bare RETURN and EOF absence have distinct callee/caller errors under
the [current CALL contract](levelc-architecture.md#call-contract).
The imports are checked against actual runtime metadata by the Level B reader,
not guessed from source names or supplied by the native compiler.

The [evaluation pair](../examples/step03/README.md) exposes logical differences:
G creates `logical.rhs`/`logical.skip`/`logical.join` blocks. Classic contains an
ordinary call before `crexx.c.and`/`crexx.c.or`, so both operands are evaluated.
The [numbers pair](poc-scope.md#runnable-source-examples) retains exact Classic
literal identity, explicit NUMERIC updates and unset-name reads, alongside G's
canonical integer/decimal/default contracts.

## RXAS execution and implemented optimisation

STEP05 requests exact evaluation from the operation's registered service.
No evaluator is registered for context-dependent Classic operations. Exact
literal `0`/`1` supplies a separate derived Boolean branch fact while the
effectful runtime truth check remains. An unknown numeric context prevents
contextual folding; a possibly
failing or effectful operation is retained unless the pass proves its required
premises. Propagation of G local slots does not establish a right to propagate
arbitrary Classic pool reads. Proved branch pruning must retain preceding
observable evaluations and errors.

STEP04 selects these operations into cREXX ABI calls/instructions, assigns
stable registers and emits RXAS using Level L's emitter library, all in Level B.
The [actual STEP04 outputs](../examples/step04/README.md) include the complete
pipeline and literal-only pairs. Both pipeline executables print `10`, `0`, `3`.
The refreshed Classic image explicitly links `library.rxbin`, `llctarget.rxbin`,
`rxfnsc.rxbin`, `classlib.rxbin` and `rxunicode-core.rxbin`; it has no G aggregate
or compiler dependency. Its single `llctarget.lengthvalue` call uses the shared
Classic BIF body through the adapter. The nine-byte constant is not reduced to
a byte count by the compiler.
The [backend reference](backend.md) explains the target records, register maps,
call windows, Classic adapter and source/error handling. The STEP03 consumer stops after source/IR admission; execution requires the
remaining assembler/linker/VM stages.

## A syntax error

The deliberately malformed [example](../examples/step03/syntax-error-g.crexx)
uses CRLF and Unicode before a missing operand. The
[retained actual message](../examples/step03/syntax-error-g.txt) gives filename,
byte offset, line and Unicode column, the expected-token set, source excerpt
and caret. No successful graph is available. The permanent suite checks these
fields, missing THEN/END, misplaced ELSE, invalid calls, unterminated quotes and
comments, invalid UTF-8/NUL, profile refusals and semantic errors on both VMs.
