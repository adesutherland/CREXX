# Actual C/G compilation outputs

The original fixture/view baseline was generated by the implemented B-only
compiler using Level L, then assembled, linked and executed on 15 October 2026.
The current Classic pipeline refresh is qualified separately below. These are complete
outputs, including metadata, activation setup and cleanup. No shared IR
optimisation is enabled. See the [backend](../../doc/backend.md) for the
register/call algorithm and [current plan](../../PLAN.md)
for the original qualification boundary. The subsequent essential provenance
correction refreshes these outputs; its bounded proof is recorded in
[current plan](../../PLAN.md).

The Classic IR and RXAS views use the current borrowed-context ABI, with
compiler IR optimisation and assembler optimisation both disabled. Earlier literal,
pipeline and error execution is retained for the unchanged body behavior. The
current C views add the approved header Name read, qualified by focused OPTIONS
execution. The earlier DO checkpoint refreshed the maintained pipeline IR/RXAS
views for state-free DO/WHILE lowering and the contextual truth helper.
The current pipeline additionally uses shared PARSE acquisition/execution for
ARG, with the nine-name fatal bridge introduced by PARSE. Its refreshed RXAS
was assembled without assembler optimization, linked with the explicit runtime
below and executed for `10`, `0`, `3`; unchanged literal/error proof is reused.
The complete pipeline module has 893 executable instructions, 82 calls and
wrapper/body frames 16/77/34, with 53 source records. Counts include wrappers
and cold handlers but exclude external helper bodies; they are not speed claims.
Compared with the earlier 734-instruction/75-call view, 70 additional
instructions come from PARSE's five extra fatal names in each of two routines.
The remaining 89 instructions and seven calls per ARG are conservative shared
source acquisition/checkpoint/executor costs. C-OPT-01/02/05 retain their
ownership and ABI/lifetime closure requirements in the current plan; this is
not a minimal-frame or performance result.

Both literal sources say `01`. Classic preserves the text spelling; G parses
the integer and converts its value to text. The complete Classic output calls
the existing dynamic runtime through `llctarget`; it does not reduce that
activation to the two hand-written instructions in the earlier review.

The pipeline pairs include assignment, arithmetic, branch, loop, local routine,
RETURN, SAY and LENGTH. Read the [tree/IR walkthrough](../../doc/pipeline-walkthrough.md)
alongside these files. `%N` identifies an IR value; `rN` identifies an assigned
VM register. `llfN` and `llbN` are internal function and block labels.

From this directory, with the installed bin directory in `CREXX_BIN`, regenerate
and execute the G literal with:

```sh
"$CREXX_BIN/llrxc-g" -n -i "$CREXX_BIN" -o literal-g.rxas literal-g.crexx
"$CREXX_BIN/rxas" -n literal-g.rxas
"$CREXX_BIN/rxlink" -o literal-g-linked literal-g.rxbin "$CREXX_BIN/library.rxbin"
"$CREXX_BIN/rxbvm" --no-autoload literal-g-linked.rxbin
```

For Classic use `llrxc-c` and link the program with `library.rxbin`,
`llctarget.rxbin`, `rxfnsc.rxbin`, `classlib.rxbin` and `rxunicode-core.rxbin`.
The class library supplies the dynamic pool's map; the standalone B Unicode
core supplies Classic's Unicode procedures. This closure has no G aggregate.
Do not add `rxfnsg.rxbin` alongside the standalone core: a linked image has one
Unicode provider. For the larger examples the source path is
`../step01/pipeline-c.crexx` or `../step01/pipeline-g.crexx`. The CLI records the source basename, independently of its physical directory;
service callers can pass a deliberate relative logical name to disambiguate
files with the same basename. The IR dumps use the existing
`frontends/noopt/frontend-probe-linked.rxbin` inspection consumer with arguments
`c` or `g`, the source file, and the runtime directory. Generated bytecode
and linked executables belong in a build/temp directory; only readable stage
outputs are retained here.

## Manual smoke test on the development Mac

Build and install the explicitly selected research component as described in
[the compiler guide](../../README.md). Set `crexx_bin` to that installed `bin`
directory, which contains both commands and their runtime dependencies:

```sh
crexx_bin=/path/to/installed/crexx/bin
crexx_examples="$PWD/research/level-l/compilers/examples/step01"
(
  crexx_work=$(mktemp -d)
  trap 'rm -rf "$crexx_work"' EXIT
  cd "$crexx_work"
  "$crexx_bin/llrxc-g" -n -i "$crexx_bin" -o demo-g.rxas "$crexx_examples/pipeline-g.crexx"
  "$crexx_bin/rxas" -n demo-g.rxas
  "$crexx_bin/rxlink" -o demo-g-linked demo-g.rxbin "$crexx_bin/library.rxbin"
  "$crexx_bin/rxbvm" --no-autoload demo-g-linked.rxbin
  "$crexx_bin/llrxc-c" -n -i "$crexx_bin" -o demo-c.rxas "$crexx_examples/pipeline-c.crexx"
  "$crexx_bin/rxas" -n demo-c.rxas
  "$crexx_bin/rxlink" -o demo-c-linked demo-c.rxbin "$crexx_bin/library.rxbin" "$crexx_bin/llctarget.rxbin" "$crexx_bin/rxfnsc.rxbin" "$crexx_bin/classlib.rxbin" "$crexx_bin/rxunicode-core.rxbin"
  "$crexx_bin/rxbvm" --no-autoload demo-c-linked.rxbin
  cat demo-g.rxas demo-c.rxas
)
```

Each run should print `10`, `0`, `3` on separate lines. The four commands are
compile source through IR to RXAS, assemble bytecode, link runtime dependencies,
then execute. Open `demo-g.rxas` or `demo-c.rxas` to inspect emitted assembly;
the original sources remain in the examples directory. The commands use the
new B/Level L compilers. Classic's additional link inputs supply its target
adapter, dynamic runtime, map and Unicode services. The commands disable shared
IR optimisation with `-n` and assembler optimisation separately with `rxas -n`.
Both compilers enable shared IR optimisation by default when `-n` is omitted.
They currently implement the admitted PoC profile; full language coverage
remains later work.

## Error provenance

[error-c.crexx](error-c.crexx) ([RXAS](error-c.rxas)) and
[error-g.crexx](error-g.crexx) ([RXAS](error-g.rxas)) print `1`,
then fail at `say 1 / 0`. Compile, assemble, link and run them with the same
commands above (substitute the source/output stem). C exits 28 and retains
`error-c.crexx:3:5: RXC-LC-42.3` as authored context, with the original
Classic runtime helper as the fault. G exits 5 and attributes its direct
division instruction to `error-g.crexx:3:5`. Both stop before printing another
value. Their `.srcstep` expression range is columns 5–10, end-exclusive.

The C handler uses existing `signalorigin` after formatting the context. Its
location register remains necessary because the VM has unwound deeper frames.
Generated entries have an explicit no-source record; clause IDs are zero until
real clause associations are implemented. This is a bounded fatal-error profile,
not complete TRACE, condition trapping or INTERPRET provenance.
