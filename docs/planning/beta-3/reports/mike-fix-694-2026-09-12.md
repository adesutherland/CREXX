# Issue 694: exposed-global metadata and incomplete array contracts

The reduced provider/consumer in [#694](https://github.com/adesutherland/CREXX/issues/694)
crashes both compiler modes at `fa887be158213403b9b1de458cfdecc7e4c86122`.
The provider declares `values = .int[-1 to 1]`, writes `values[-1] = 42`,
and exposes the global and its initializer. The consumer imports only the
assembled provider, calls the initializer and reads `values[-1]`.

## Cause and repair

The producer walked a procedure's scope instead of its enclosing namespace.
It also treated the body's single symbol association as the list of globals;
one AST node cannot retain several such associations. Global metadata now uses
the namespace symbols and their actual live uses in each procedure, method or
factory, with matching metadata clears.

The reader looked for exposed registers on the metadata chain, although the
existing bytecode format gives exports a separate chain. RXAS and RXBIN imports
now walk the module's export chain and find the corresponding type record on
its own metadata chain, including modules in a shared constant pool. Object
and reference contracts also load the class into the actual consumer, even
when the private parsed type declaration already has a cached type.

Two retained LLDB stacks establish the crash sequence: early constant folding
indexes absent bounds in `rxcp_opt.c`; after guarding that early access, an
explicitly unknown imported contract can still reach `rxcp_emit_reg.c` without
array bounds. Final type validation now diagnoses absent or excess dimensions
before register allocation. Earlier checks verify bounds exist and the index
is within the shape. Assignment upper-bound checking uses one lower-bound
offset, correcting its previous double addition for non-one-based arrays.

The maintained Apple-ASan replay additionally exposed SAN-008 in the earlier
type-setting pass. `ast_chdi()` returns a signed child ordinal, including `-1`
on failure, while the symbol's dimension count is `size_t`. The final-zero
array-size shorthand now requires a non-negative ordinal whose cast value is
strictly below the declared dimension count before reading `dim_base`. Both an
extra final `1` and an extra final `0` therefore reach the existing
`ARRAY_DIMS_MISMATCH` diagnostic without reading beyond the bounds table;
valid one-based final-zero size queries retain their existing rewrite.

This preserves existing type inference and legacy bytecode compatibility.
Missing or clear-only metadata can use the caller's explicit complete type;
`.unknown` does not erase a known caller declaration. An undeclared read with
no usable array shape is rejected. A first untyped indexed write retains the
existing one-based array inference and its range checks. Present empty or
malformed metadata produces `SYNTAX_ERROR_IN_IMPORT_DECL`. No bytecode format
or language syntax changes are required.

## Qualification

`binary_global_import_types` exercises complete object, object-array, string-array,
bounded multidimensional integer and live-reference globals through source,
opt-in assembly, bytecode and linked shared-pool imports. Compiler and assembler
optimization are independently enabled and disabled; explicit linking and both
VM dispatch variants verify exact values. Negative cases cover bounds, excess
dimensions, conflicting declarations, and missing, clear-only, unknown, empty
and malformed metadata. Legacy caller declarations must still execute correctly.

The final matrix contains 80 positive executions and 176 negative compile
checks. Its main runtime output is exactly
`hello:value:42:17:7:31:37`; legacy caller-declared imports print exactly `42`.
Both `grid[-2, 1, 1]` and `grid[-2, 1, 0]` are required to report
`ARRAY_DIMS_MISMATCH` in every import route and compiler mode.
