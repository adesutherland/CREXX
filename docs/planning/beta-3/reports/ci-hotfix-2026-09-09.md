## RXPP macro lookup: SAN-QA-014

Commit `82730b495` changed `CMD_loadMacro` from `normalisePath(syspath, ...)`
to `normalisePath(inpath, ...)`. The documented contract resolves relative
macro directories against the selected macro library. Text Inspector keeps its
source files in the source tree and stages `ui/*.rxpm` beneath its build-tree
macro library. Source-relative lookup therefore omits its node, command and
launcher expansions. The generated files still compile, but the application
is incomplete: generation reports missing logical node construction, core
tests miss cancellation rendering, and TUI/PTY tests cannot run the application.

The previous `rxpp_loadmacro` fixture put source and macro library in the same
directory, so both implementations passed it. The strengthened fixture separates
those roots and installs a conflicting source-relative package. It fails before
repair with `say "wrong source works"` in `loadmacro-before.log` and passes
after restoring the documented root. Other path-parsing changes remain intact.

## Exited child termination: SAN-QA-008

The strengthened hosted provider diagnostic finally identifies the failing
stage: `Failure spawn terminate. Details: RC=1 Text=Operation not permitted`.
The returned provider completion was state 2 / error 17 instead of timeout
state 4. No ASan memory report accompanied this failure.

The bounded wait first checks `waitpid(WNOHANG)`, then deadline handling stops
redirect I/O before signalling the process group. The child can exit between
those operations. A deterministic native probe forks a child into its own
group, observes its exit using `waitid(WEXITED | WNOWAIT)`, and then calls
`kill(-child, SIGKILL)`. On the local Darwin host this returns `-1`, errno 1.
The permanent `rxspawn_posix_termination` test reproduces that result against
the original signalling implementation (`termination-before.log`).

Apple's [XNU process-group signalling implementation](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/kern/kern_sig.c#L1580)
filters exited group members and can report `EPERM` when none remain eligible.
The repair accepts this result only after a nonblocking, non-reaping exit
observation confirms the owned child's terminal state. The caller retains its
ordinary `waitpid` and group-only descendant cleanup. Live-child permission
errors, observation failures and unrelated signal errors remain errors.

The regression covers real live/exited children in owned and inherited groups,
plus injected `EPERM` on Linux, live-child rejection, direct-child rejection,
and unrelated-error rejection. A pipe and `waitid` establish the states;
there is no scheduling sleep. The existing saturated endpoint test retains its
100 ms semantic deadline and typed completion assertion.
