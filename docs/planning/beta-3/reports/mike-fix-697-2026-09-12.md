## Remaining race and historical escape

The 9 September repair handled an exited child already observable through
`waitid(WEXITED | WNOHANG | WNOWAIT)`. Its regression explicitly waited for
that state before signalling, so it did not exercise the earlier exit
transition. On Darwin, group signalling can already reject the exiting child
while nonblocking `waitid` still returns no terminal record.

A native probe creates a private group, proves that signalling its live child
is permitted, then releases the child through a pipe to exit. It observes
`kill(-child, 0)` returning `EPERM`, calls the production termination helper,
and finally reaps the child. All 1,000 before-repair iterations returned a
helper failure despite the child's subsequent successful exit. The identical
probe after repair reports zero helper failures in 1,000 iterations. The
probe runs outside the tool sandbox with approval so sandbox signal policy
cannot account for the result. No child remains after the probe.

This fits the separate process-group iteration and terminal-observation paths
in Apple's [group signalling implementation](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/kern/kern_sig.c#L1580)
and [waitid implementation](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/kern/kern_exit.c#L2920).
The local before/after probe establishes the relevant observable behavior;
this source comparison does not establish the exact kernel revision used by
the hosted runner.

## Repair and regression

The private helper extends its existing owned-group `ESRCH` direct-child retry
to group `EPERM`. The positive PID still belongs to an unreaped child, so it
cannot have been reused. A successful direct signal confirms delivery or an
already exited child. If direct signalling is denied too, only the existing
non-reaping terminal observation can accept that result. A real permission
failure on a live child remains an error. Post-reap descendant cleanup still
addresses only the owned process group.

The permanent `rxspawn_posix_termination` test injects a group-only denial while
retaining real direct-child signalling and ordinary wait ownership. The old
helper fails this case; the repair terminates the child and leaves it for the
parent to reap. Existing live/exited, owned/inherited, true denial and unrelated
error cases remain. The byte provider retains its original semantic deadline,
parallel scheduling and exact typed-timeout assertion. No suppression, test
exclusion, waiver or language/API change is part of this repair.
