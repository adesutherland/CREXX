# Issue 695: preserve child-exit signal policy across DO PARALLEL

Mike's process report exposed a controller hang after an isolated worker
published pre-start `TRANSPORT_LOST`. The native provider had one terminal
request, no active request, completion generation 1, and had already marked its
completion observed. The controller nevertheless waited again in
`process_completion_wait`.

## Reproduced mechanism

The retained interpreter trace records `POSIX_CHLD` immediately after
`CHANWAIT`, followed by the compiler-generated DO PARALLEL signal handler and
its abort/join path. `rxvm_channel_wait()` marks native completion delivery
observed before returning the encoded document. The Level B `channel_impl.wait()`
must then decode that document and write `_completions[index]` and
`_terminals[index]`. Unwinding between those steps leaves the class cache empty
although the provider will not deliver the same completion again.

An independent source-only reduction makes the signal-policy error
deterministic. With `signal posix_chld` immediately before a parallel expression,
the program returns 42. Moving only that signal inside DO PARALLEL before the
task call returns zero because the generated catch-all silently exits the
block. This reproduces with optimization enabled and disabled and with both
`rxbvme` and `rxvme`. The VM's ordinary `POSIX_CHLD` response is ignore; the
generated handler was overriding it.

The pre-start transport-loss mechanism remains independently covered by
`rxvmchannel_process_crash_replacement`: it forces loss before `STARTED`,
requires terminal state 7, and proves the replacement worker succeeds. The
source reduction and this native regression bracket the two sides of the
original trace without adding a production test hook or depending on timing.

## Repair

The compiler-generated parallel guard now names the existing controller-failure
signals explicitly and omits only `POSIX_CHLD`. Child-exit notification therefore
continues under the caller's already selected signal policy, including the VM's
default ignore response. The generated guard still aborts, joins and re-raises
for `FAILURE`, `ERROR`, conversion and range signals, channel/task failure,
termination signals, and the other prior controller-failure cases.

This changes neither authored `ON SIGNAL` syntax nor its empty-name catch-all
meaning. It does not discard `POSIX_CHLD` globally, change provider completion
delivery, weaken task failure policy, or add a second completion observation.
