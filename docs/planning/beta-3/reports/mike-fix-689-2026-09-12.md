# Issue 689: inline return conversions

The [optimizer wrong-result report](https://github.com/adesutherland/CREXX/issues/689)
remains reproducible after the separate #686 repair at
`70296613d88a4b1d8345b6e69e07d47157f03273`. Mike's original source and query
`functor(foo(a,b,c),F,A).` print `F = foo, A = 0` with compiler optimization and
`F = foo, A = 3` without it; all process exits are zero.

## Cause and correction

The reduction needs an integer local initialized to zero, a string-returning
wrapper, and a string-returning counting function with empty/nonempty return
paths. Calling the counting function directly works. Inlining the wrapper
creates a new assignment after final type validation, retaining the cloned
return expression's string target. The optimized assembly copies the block's
string result into integer storage without `stoi`.

The statement inliner now applies the caller's target to that result. When the
return expression must first become the callee's declared result type, it
materializes that intermediate type before applying the caller conversion.
Method return capture preserves the declared conversion before receiver
copyback. This retains the supported inline shape and existing syntax and
conversion rules; no inlining threshold or general call fallback changes.

A second reduced example proves why both conversions matter: a string `003`
returned through an integer declaration and assigned to a string must become
`3`. The unpatched inliner retained `003`, including through a state-mutating
method. The candidate preserves `3` and the method's state update. Invalid
integer text continues to raise `CONVERSION_ERROR` with exit 6.

## Regression and validation

`inline_return_conversions` exercises combined source, source imports and binary
imports, each with compiler optimization on/off, assembler optimization on/off,
and portable/product VMs. All 24 positive runs assert exact output and all 24
negative runs assert the conversion error and exit status. The combined case
requires the nested wrapper to remain inlined; all arrangements require the
converted single-return function and state-mutating method to remain inlined.
Imported wrapper execution also checks the existing ordinary-call path.

- Before repair, the regression reports `nested: 0`, `empty: 1`,
  `canonical: 003`, `method: 003 1` instead of `3`, `0`, `3`, `3 1`.
- Mike's original query passes all eight compiler/assembler/VM combinations
  through explicit compile/assemble/link/run on the Release product.
- The final Release regression passes (24 positive and 24 negative runs).
- Focused normal Debug and maintained Apple ASan panels each pass 4/4, including
  the conversion regression and existing receiver/reference/import checks.
  Apple ASan does not provide LeakSanitizer; Linux LSan remains a hosted gate.
- Full normal Debug correctness QA passed 2,300/2,300 (630.72 seconds),
  excluding only the separate `performance-measurement` lane. Code/test hashes
  remained unchanged throughout qualification.
- Hosted results will be linked from the issue after publication. This record
  does not establish release readiness or close unrelated sanitizer items.
