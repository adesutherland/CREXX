# CREXX 1.0.0 Beta 3 Release Notes

_Status: prepared release notes, 30 September 2026. Target tag:
`v1.0.0-beta.3`. This version remains development content until the tag and
qualified release assets exist; beta 2 remains the latest completed beta._

Beta 3 brings together the Level B toolchain and libraries, accumulated
compiler/runtime and performance work, the initial Level G overlay, and
mainframe portability repairs. It is a feature-bearing Release 1 beta.
The [candidate preparation record](../planning/beta-3/mainframe-integration-2026-09-30.md)
records integration and qualification status. The
[Release 1 plan](../release-1-plan.md) owns the continuing beta schedule;
the original milestone history remains there.

## Toolchain and runtime

- `rxc`, `rxas`, `rxlink` and the product VM retain one common language and
  RXBIN 007 format. The explicit switch and direct-threaded engines remain
  available where supported by the C compiler.
- Binary memory, immutable binary constants and packed jump tables support
  the accumulated compiler and assembler optimizations. Conservative eligibility
  and ownership checks preserve optimized/unoptimized behavior.
- Late module loading rebuilds runtime interface/factory indexes. Explicit
  library paths let applications select an approved image without path search.
- Source imports preserve namespace independence, first-root precedence and
  multiple providers in that root. Import and mandatory compiler-exit failures
  retain their cause and return failure.
- Checked compression workspace and portable imported-procedure sentinels
  support constrained and cross-width builds. Allocation failure guards include
  compiler AST creation and preserve RXBIN record-table exhaustion diagnostics.
- The driver supports dependency-aware project builds, SDK packaging and
  ordinary same-source lock-and-wait ownership. RXPP remains a visible,
  separate stage for `.rxpp` sources.

## Libraries and initial language surfaces

- Level B remains the primary implemented language. Text is UTF-8 and binary
  values preserve arbitrary bytes. Richer Unicode services use explicit APIs.
- The initial Level G task/parallel surface includes pool and scope classes,
  local and isolated-process execution, bounded byte endpoints, structured
  process redirects and concurrent HTTP client/server services. Use
  `OPTIONS LEVELG`; the surface remains initial rather than a final R1 contract.
- `rx_hash` provides one-shot, hexadecimal, immutable incremental-state and
  bounded-memory file SHA-256 procedures. Invalid state and file errors have
  explicit failure contracts; see the [SHA-256 API](../books/crexx_library_reference/rxhash.md).
- `rxvector` adds an immutable binary float32 `.vectorindex`, checked import/
  export, exact cosine search, deterministic ties and independent copy/close
  lifetimes without a USearch/C++ dependency. See the
  [API and RXVIDX/1 format](../books/crexx_library_reference/rxvector.md).
- Read-only JSON indexed access avoids copying immutable backing buffers.
  Native provider factories and method bindings remain the supported construction
  route; provider dependencies are explicit in native packaging.
- RexxScript remains a separate interpreted product with standalone and embedded
  entry points. It is not the compiled Level C route. Beta 3 retains six bounded
  Level C execution-lowering slices; unsupported forms fail closed.

## Mainframe text and failure handling

The mainframe repair uses the existing shared codec. Native tool entry points
select raw SDK I/O; cREXX converts text at its platform boundary exactly once.
UTF VM console reads decode IBM1047, and SAY, text stdout/stderr, tool diagnostics
and emergency memory diagnostics use native output. Console encoding is
independent of the file `-E` selector. BYTE VM reads and binary/byte operations
retain raw bytes. `version()` documentation and its regression include `tso`.

Selected file encodings remain attached to an open stream. Sequential text
read/write/append uses the existing wrapper; text update modes fail before
opening, and converted-text seeking is unavailable. The frozen native SDK's
append capability remains a platform limit. Binary files bypass conversion.

The selected mainframe PoC/alpha scope is CMS31, TSO31 and TSO64 RMODE ANY.
Lab builds have bounded native console/file/diagnostic and compiler-chain
receipts. Those builds are separate from formal upstream beta assets: exact
packaged revision, SDK/runtime inputs and manual z/OS/z/VM installation and
execution still require their own release checks. Supplementary 24-bit routes
are limited VM subsets. The Lab repaired PDOS track-transition writes and
its frozen HIGH package now passes the fresh native compiler/assembler/VM
chain and exact readbacks. That package predates the new console-signal repair;
this upstream candidate's exact native packages and modern z/OS HIGH remain
separate unqualified boundaries.

## Distribution and qualification

The current release workflow packages four separate core ZIPs: Linux x64,
Windows x64, macOS arm64 and macOS x86_64. Core packages contain no mandatory
llama/model dependency. Six matching optional llama.rexx ZIPs are built for
Linux/Windows Vulkan and CUDA, macOS arm64 Metal and macOS x86_64 CPU.
The full tag workflow requires all configured core/plugin lanes plus MinGW
and comprehensive correctness before publishing.

macOS core/plugin `.pkg` installers are conditional on successful configured
signing and notarization. Windows signing/installer evidence and any additional
formats must be checked against actual assets. Do not infer signed, notarized,
installed or device-qualified status from a source build. Final asset names,
checksums, signing status and download links belong to the actual tag release.

The preparation record distinguishes local Debug/focused sanitizer checks,
automatic development publication, Release package smoke and formal platform
assurance. Older passing sanitizer receipts qualify their recorded inputs;
they do not automatically qualify this changed candidate. Release completion
requires the exact candidate's applicable gates and no open first-party SAN item.

## Known limitations

- This is a beta, not the final stable Release 1 language/library contract.
- Full Classic Rexx compatibility and general Level C compilation remain open.
  SOURCELINE #602 remains deferred under the approved metadata-only feasibility
  decision; beta 3 does not add a complete source store.
- Concurrency remains initial and uses worker-owned VM state. Shared writable
  VM state, detached tasks and public worker identity are outside this contract.
- Native inference is optional. Package smoke does not establish every model,
  hardware/backend, memory or lifecycle qualification cell.
- Mainframe console output cannot represent every Unicode character. Default
  SAY/SAYX and UTF console FWRITE/FWRITECDPT raise `UNICODE_ERROR` when conversion
  fails, including an unrepresentable euro sign. Write/flush failures raise
  `NOTREADY`. Custom SAY callbacks retain their own output policy and void ABI.
  The new signal behavior has separate host proof; older Lab packages predate it.
- Mainframe packages are PoC/alpha products with explicit native capabilities,
  capacity requirements and separate installation proof. CMS64 and modern z/OS
  HIGH execution are not qualified by this repair.
- Experimental debugger/GPU work and broader Unicode/language proposals do not
  acquire stable status from this beta. Windows MSI/WiX/winget publication is
  outside the current release scope.
